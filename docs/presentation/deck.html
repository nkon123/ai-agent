사내 업무 조사 도우미

인터페이스 오류,

한마디로 영향도까지.

로컬 LLM · MCP · LangGraph 로 만든 AI Agent

[발표자] · [팀명] · 2026. 10

오늘 소개할 것은 인터페이스 오류 메일 한 통에서 시작해, 어떤 프로그램이 영향을 받는지까지 한 번에 조사하는 AI Agent 입니다. 사내 PC 안에서 로컬 LLM 으로 돌아갑니다.

해결하려고 한 것

오류 메일 한 통.

영향도까지 다섯 단계, 전부 손으로.

오류 메일에서 인터페이스 ID 를 찾고, DIMS 에서 타겟 테이블을 다시 확인한 뒤, 소스에서 테이블과 컬럼을 차례로 검색해 영향을 판단했습니다.

인터페이스 오류 메일이 오면 담당자가 하는 일은 늘 같았습니다. 메일 확인, 인터페이스 ID 와 오류 내용 확인, DIMS 에서 타겟 테이블 재확인, 소스에서 테이블 검색, 그 소스에서 컬럼 검색. 이 반복을 줄이는 것이 목표였습니다.

해결하려고 한 것

다섯 단계를 한마디로.

기존 — 사람이 직접

  1. 오류 메일 확인
  2. 오류 내용에서 인터페이스 ID 와 오류 내용 확인
  3. DIMS(인터페이스 시스템)에서 타겟 테이블 재확인
  4. 소스에서 그 테이블 검색
  5. 찾은 소스에서 문제 컬럼 검색, 영향 판단

지금 — AI Agent 에게 한마디

“오늘 인터페이스 오류 확인해줘”

  1. 오류 메일을 골라 읽음
  2. 인터페이스 ID 와 원인 컬럼·문제(길이 초과 등)
  3. 인터페이스 마스터에서 타겟 테이블
  4. 그 테이블을 쓰는 소스를 모두 찾음
  5. 컬럼이 나온 줄마다 영향 판정, 표와 소스로
왼쪽이 지금까지 사람이 하던 순서입니다. 오류 메일을 확인하고, 오류 내용에서 인터페이스 ID 와 내용을 보고, DIMS 에서 타겟 테이블을 다시 확인한 뒤, 소스에서 테이블을 검색하고, 그 소스에서 문제 컬럼을 검색했습니다. 오른쪽은 같은 다섯 단계를 한마디로 요청한 결과입니다. 단계는 그대로이고 잇는 일을 에이전트가 합니다. 3번은 DIMS 화면 대신 인터페이스 마스터를 조회합니다.

해결하려고 한 것

만들면서 지킨 네 가지.

한마디로 끝까지

작은 로컬 모델은 툴을 이어 부르지 못합니다. 단계를 잇는 일은 모델이 아니라 에이전트가 합니다.

규칙 먼저, LLM 은 빈칸만

ORA 메시지, 별칭, 호스트 변수처럼 정해지는 것은 규칙으로 확정하고 애매한 줄만 LLM 이 봅니다.

‘모른다’와 ‘아니다’를 구분

판정할 수 없거나 규칙과 LLM 이 갈리면 ‘확인 필요’로 남깁니다. 행마다 근거를 함께 보여 줍니다.

사내 PC 안에서

로컬 LLM 으로 외부 전송이 없습니다. 메일과 DB 는 읽기만 하고, 발송·수정은 자동으로 하지 않습니다.

첫째, 소형 모델의 한계를 인정하고 단계를 에이전트가 잇습니다. 둘째, 규칙으로 정할 수 있는 건 규칙으로. 실제로 LLM 이 틀린 줄은 전부 규칙으로 맞출 수 있는 줄이었습니다. 셋째, 모르는 건 모른다고 표시합니다. 넷째, 모든 것이 사내 PC 안에서 돌아갑니다.

시연 01 · 한마디

원인부터 영향까지,
한 화면에.

  • 오류마다 원인과 메일 원문 줄
  • 원인 컬럼이 있으면 그 컬럼을 쓰는 줄마다 영향 판정
  • 원인 컬럼이 없으면 도착 테이블을 읽는 곳·쓰는 곳으로
  • 같은 질문엔 늘 같은 모양의 답
실제 답 화면입니다. 오류 두 건이 같은 모양으로 나옵니다. 주문 오류는 메일에 적힌 원인 컬럼, 길이 초과로 그 컬럼을 쓰는 줄마다 영향을 판정했습니다. 재고 오류는 메일에 컬럼 정보가 없는 timeout 이라, 도착 테이블 IF_STOCK_TMP 를 읽는 곳은 영향 있음, 쓰는 곳은 확인 필요로 나눴습니다. 결과를 모델이 다시 쓰지 않아 같은 질문에는 늘 같은 모양으로 나옵니다.

시연 02 · 03 · 표와 소스

의심 줄은 바로 소스로.

  • 판정 · 근거 · 규칙 추정을 한 표에
  • 엑셀에 붙여넣기용 복사, CSV 저장
  • 줄 더블클릭 → 앞뒤 10줄, 그 줄과 컬럼 강조
  • 소스 루트 밖 파일은 열지 않음
표로 보기에서는 줄마다 판정과 근거, 규칙 추정이 함께 나옵니다. 규칙과 LLM 이 갈린 줄은 영향 없음이 아니라 확인 필요로 남습니다. 의심되는 줄을 더블클릭하면 그 줄 앞뒤 소스가 줄 번호와 함께 뜨고, 해당 줄과 컬럼 이름이 강조됩니다.
